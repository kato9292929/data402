## 2. 何をどう数えるか

規則は変えない。入力の選び方と、数え方の単位だけをここで決める。

- **入力**：対象の各エンドポイントの、上限以前で最も新しい行（すべて 1.1.0 の実行の行）。10-08 の数字は、その日の
  1回の実行の行（1エンドポイント1行）から出したので、同じ形になる。
- **W・W'・決済基盤の候補・最多の受取先のホスト数・payTo を読めたホスト**：`src/census/research/payto-summary.mjs`
  （spec/10 `c856aae` の W と `c56f71a` の切り分けを実装したもの、移管時のまま）を、`--network Solana` とカタログ
  `endpoint@432b3bf` で、変えずに走らせる。入力は 10-08 の形式に変換する（`figures.mjs`。`alive` の行は Solana の
  `accepts` を `network_norm: solana` で渡し、それ以外の行は `accepts` を空にして HTTP の状態を渡す）。
  10-08 の生データ（`data/payto-observations.jsonl`）でこの経路を走らせると、既に出ている W 1.64（149 / 91）・
  W' 1.56（140 / 90）・最多の受取先 23 が再現することを確かめてある。
- **相異なる受取先**：W の分母（payTo の数）。
- **ホストの status 内訳（6区分）**：spec/11 4節の規則（どれかのエンドポイントの最新行が `alive` なら `alive`、
  でなければ最新行のうち最も新しいものの status）。エンドポイント単位の内訳も併記する。
- **観測データの行数**：上限以前の全行（過去の実行の行を含む）。
- **feePayer を保存した行数**：上限以前の全行のうち、`extra` に `feePayer` があるもの。
- **単位**：全数なのはホスト単位だけ。エンドポイント単位では 501 / 6,016（1ホスト最大4本）。数字と一緒に書く。
